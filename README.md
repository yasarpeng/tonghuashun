# 同花顺（高仿版）项目 README

## 项目简介

一个高仿同花顺的股票行情与交易模拟 App，界面、配色、行情刷新节奏、持仓页、资产页均高度还原真实同花顺。核心定位不是炒股工具，而是一款**社交场景下的“资产可视化道具”**——用真实感的界面，帮你体面地解决一些不方便直说的问题。

> 免责声明：本项目仅供学习 UI 开发与个人娱乐使用。行情 / K线 / 分时 / 五档来自新浪、腾讯的**公开免费接口**；交易、持仓、委托、成交为**本地模拟**，不接入任何真实券商，也不会产生任何真实委托。

---

## 核心用途

### 1. 借钱拦截器（主打功能）

当有人找你借钱时，打开这个 App，把手机递过去：

- 首页一片环保色，自选股全绿，跌幅 -6% 起步；
- 总资产页面显示“今日亏损 48,762.31”；
- 持仓页满屏套牢，最惨一只浮亏 -63%；
- 银行卡余额：**可用 1,286.44 元**，其余全部“银证转账在途”或“已被冻结”。

然后你只需说一句：

> “你看，我的钱都在股市里，现在割肉也来不及啊。”

对方通常会露出同情甚至愧疚的表情，借钱话题自然终止。**比你直接说“不借”更委婉，比编故事更可信。**

可选增强模式：

- **一键切换“深套模式”**：全屏绿色，总亏损数字自动滚动；
- **“跌停板排队中”提示**：模拟挂单卖出无法成交；
- **“老婆管钱”备注**：在账户页加一行小字“本账户由配偶实时监控”。

### 2. 反向装穷 / 反向炫富

- 想低调时：打开“亏损版”界面，谁看了都觉得你惨。
- 想暗示实力时：切到“盈利版”，持仓一片红，总资产七位数起步，但嘴上说“都是浮盈，没卖不算钱”。
- 两种版本一键切换，同一部手机，两种人生。

### 3. 拒绝推销 / 拒绝拼单 / 拒绝请客

- 健身房推销：“哥，办张年卡吧。” → 打开 App：“我这个月亏成这样，饭都快吃不起了。”
- 同事拼单奶茶：“一起点吗？” → 打开持仓页：“套着，没钱。”
- 朋友聚餐让你请客：“你最近不是赚了吗？” → 切到今日亏损页：“赚的全吐回去了，还倒贴。”

### 4. 情绪缓冲道具

- 自己心情不好时，看着满屏绿色，产生一种“反正大家都在亏”的莫名安慰。
- 或者反过来，看着模拟账户一路长红，体验一把“如果当初买了”的平行人生。

### 5. UI 学习与前端练手

- 完整复刻同花顺的配色体系（红涨绿跌 / 深色模式 / 行情闪烁）；
- 练习高频刷新、数字滚动、K 线绘制、分时图动画；
- 可作为 React Native / Flutter / 鸿蒙 / 小程序 的多端练手项目。

## 技术要点

- 行情数据：新浪（实时/指数/五档）+ 腾讯（日K/分时/qt 扩展字段）公开接口；
- 配色：严格对齐同花顺红涨绿跌，A 股用户一眼可信；
- 图表：分时图 / 蜡烛图全部用 Compose Canvas 自绘，无第三方图表库；
- 交易：全部按**你填的价格**成交（买入/卖出页与下单页都是"点了就成交、填多少按多少"），撤单、成交记录齐全；
- 隐私：账户与持仓只存在**本机**（SharedPreferences），不上传、不联网同步，也不真实交易。

## 使用建议

1. 提前把“亏损版”数据调好，亏损金额建议在 3 万～50 万之间，太假没人信；
2. 持仓股选几只知名白马，套牢理由更充分；
3. 不要主动展示，等对方开口借钱时再“无意间”打开；
4. 配合叹气、揉太阳穴、看窗外等微表情，效果更佳；
5. 如果对方也是股民，慎用——他可能会跟你聊起 K 线，穿帮风险较高。

## 如何在 Android Studio 打开并运行

### 前置要求

- Android Studio（推荐 Koala 2024.1 或更新版本）
- JDK 17（Android Studio 通常自带）
- Android SDK Platform 34

### 步骤

1. 用 Android Studio 选择 **Open**，打开本项目根目录 `tonghuashun/`。
2. 首次打开会自动执行 Gradle Sync，下载依赖（需联网）。
3. 若提示缺少 SDK 34，按提示在 SDK Manager 中安装。
4. Sync 完成后，选择一个模拟器或真机，点击 **Run ▶**。

### 命令行构建（可选）

在已安装 JDK 17 + Android SDK 且设置了 `ANDROID_HOME` 的环境下：

```bash
# 编译 Debug APK
./gradlew assembleDebug

# 安装到已连接设备
./gradlew installDebug
```

生成的 APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。

## 说明与限制

- **行情来自公开接口**：股票池、指数、K线、分时、五档取自新浪 / 腾讯免费接口，行情随交易日实时变化；接口失败时对应区域显示 `—` 或"暂无数据"，不会崩溃。
- **板块、资讯、理财内容为静态演示数据**，不随时间变化。
- 交易为 **本地模拟**：下单一律**按你填写的价格成交**（不按现价），不执行任何真实交易逻辑；账户、持仓、委托、成交记录与自选股会**持久化到本机**（SharedPreferences），**退出 App 后再次打开仍然保留**。
- 本项目仅用于技术学习，与同花顺官方无任何关联。

## 本轮优化记录（对照真机「同花顺 2」逐页录制后修正）

对照真机 App 逐页截图、走查交互后，本轮修复/补齐了以下差异点：

1. **底部导航栏被染成粉白**：Material 3 的 `NavigationBar` 默认带 3dp 色调高度（tonal elevation），会把纯白底栏叠加成 `#FDEFF0`。真机底栏是纯白，已改为 `tonalElevation = 0.dp`。
2. **自选页长时间空白**：原实现是"批量行情 → 逐只串行拉分时 → 一次性返回"，5 只自选要等十几秒才有内容。现在先出价格、再并行回填分时迷你走势，并按 5s 轮询刷新。
3. **自选页行样式**：补上真机有的元素 —— 名称按涨跌着色、`融` / `T+0` 标签、迷你走势的分时渐变填充与昨收虚线基准、工具栏的 编辑/设置 图标。
4. **首页「今天炒什么」**：真机是左右双栏（相关个股 + 涨跌分布），原来只有单栏，已补齐涨跌家数分布条。
5. **个股详情页**（差异最大的页面）：补齐周期切换（分时/日K/周K/月K，周月K由日K聚合）、九宫格指标（高/低/开 · 市值/流通/市盈TTM · 量比/换/额）、带量条的五档与成交明细、以及底部 看点/资讯/盘口/资金/简况(F10)/诊股 标签区。
6. **新增腾讯 `qt` 扩展行情接口**：原始数据源只有价格与成交量，市值/流通市值/市盈(TTM)/市净率/量比/换手率 这些详情页必备字段原先恒为 0，现已接入。
7. **行情页大盘卡片**：底色由中性灰改为跟随涨跌的淡红/淡绿，与真机一致。

> 已知的有意差异：真机个股详情页底部是「下单 / 社区 / 删自选 / 功能」，
> 本项目保留了更实用的「买入 / 卖出」直达按钮，其余结构对齐真机。

1. **新增「交易首页」**（此前本地直接进入买入页，真机是先有一个交易首页）：
   - 顶部频道栏 `A股 / 基金 / 期货 / 黄金 / 模拟` + 刷新（真机里非 A 股频道是 H5 页面，本地以占位页说明）；
   - 券商账户卡：中信证券 + `资金账户: 8800****2373` + 「多账号登录」→ 账户切换弹层（中信证券 ✓ / 添加账号 / 账户管理）；
   - 2×2 指标：总资产、总市值、总盈亏、当日参考盈亏；
   - 快捷操作 5 个：买入 / 卖出 / 撤单 / 持仓 / 查询；
   - 「9月参考盈亏」卡片、2×5 功能宫格（新股/债申购、通用回购逆回购、条件单 NEW、科创板、我的笔记、港股通交易、我的组合、行情全景、港股ETF、敬请期待）；
   - `银证转账 / 盘后固定价格交易 / 风险测评 / 交易设置 / 帮助与反馈` 列表 + 底部「退出委托」大红按钮。
2. **五个子页改为二级页**：统一加红色头部（返回 + 中信证券 **2373 + 搜索 + 刷新）与 `买入/卖出/撤单/持仓/查询` 子 Tab，可返回交易首页。
3. **修正券商配色**：交易模块跟随券商，**盈利红 / 亏损蓝**（此前误用行情页的红涨绿跌），持仓表、浮盈浮亏、五档价格全部改过来。
4. **当日参考盈亏改为真实计算**：给 `Position` 补上 `prevClose`，由持仓昨收实时算出，替换掉原来写死的 `-45.90 / -0.05%`。
5. **卖出页细节**：下单区整体走蓝色系，子 Tab 为 `持仓/委托/成交`（真机卖出页没有「自选」Tab，买入页有）。
6. **持仓页表格重做**：真机持仓列表是「两行文本 × 四列」的紧凑表格（名称/盈亏/持仓/成本 + 市值/盈亏%/可用/现价），
   行内**没有买入卖出按钮**（此前误加了），点击整行进个股详情；表头右上角补上真机有的「持仓分时 / 持仓报价模式」两个开关图标；
   `持仓资讯 | 资产分析` 之间补上竖向分隔线。
7. **各子页头部微调**：按真机，持仓页头部多一个「分享」，查询页没有「刷新」。
8. **点击持仓股的行为**（真机实测）：真机点持仓行**不会跳到个股详情**，而是在该行下方展开一条操作栏

   - `行情` → 个股详情页；`买入` / `卖出` → 带该股代码跳到下单页（预填代码、现价、可买/可卖、个股仓位）；

## 第三轮：交易数据实时化 + 持仓明细

1. **修掉「持仓价格是死的」**：交易页的持仓行情此前只进到 `_priceMap`，但**没有并入 `uiState` 的数据流**，
   而 `buildPositions()` 又在 `combine` 里单独发请求 —— 结果持仓的现价/市值/盈亏只在切页时刷新一次。
   现在把行情作为一路流 `combine(accountSnapshot, priceMap)`，`buildPositions` 改成纯函数，
   持仓表按 4 秒节奏跟着实时行情跳动（挂单撮合同步刷新）。
2. **持仓明细（点持仓行 → 「明细」）**：做成同花顺样式的底部弹层，字段全部由实时行情计算：
   持仓数量、可用数量、成本价、现价、昨收、市值、浮动盈亏/比例、当日盈亏/比例、持仓成本、个股仓位、回本涨幅
   （回本涨幅 =（成本价 − 现价）/ 现价，与真机「回本涨幅」列算法一致），底部带「查看行情 / 买入 / 卖出」。
3. **个股详情页实时刷新**：现价、涨跌幅、市值/市盈等扩展指标、五档、分时改为 5 秒轮询刷新（K线不重复拉取），
   从持仓点「行情」进去后数字会持续跳动。
4. **交易页头部「刷新」按钮接上真实刷新**，不再只是提示。

> 说明：A 股午间休市（11:30–13:00）与收盘后行情本身是静止的，此时数字不动属于正常现象。
> 可用 `curl -H "Referer: https://finance.sina.com.cn" https://hq.sinajs.cn/list=sh600519` 与页面数值对照验证。

## 第四轮：下单页自动填充 + 实时价

1. **修掉下单页选不中股票**：从持仓点「买入/卖出」传进来的是带市场前缀的 `sh600329`，
   而 `searchStocks()` 只认 6 位纯数字，解析失败 → 股票为 null → 页面上一直是 `--`。
   新增 `StockRepository.getStockByAnyCode()`，`sh600519` / `SH600519` / `600519` 三种写法都能解析，
   `searchStocks()` 也先走这条快路径。
2. **选中股票后自动回填**：代码框统一回填 6 位代码、右侧显示股票名称、委托价自动填该股最新价，
   同时拉取该股五档与分时，涨跌停价按昨收计算（`昨收×0.9 / ×1.1`）。
3. **下单页接实时行情**：现价、涨跌幅、均价、五档、分时按 4 秒轮询刷新（不会覆盖用户手填的委托价与数量）。
4. **下单页「展开」分时图**：与真机一致，默认收起，点「展开」显示该股分时（价格线 + 均价线 + 量能），再点「收起」。

## 第五轮：顶格对齐 + 自定义资金 + 点了就成交

1. **修掉交易页顶部多出一截空白**：`AppRoot` 的外层 `Scaffold` 已经处理过状态栏内边距，
   而 `TradeScreen` / `StockDetailScreen` / `OrderScreen` 各自又套了一层 `Scaffold`，
   默认会再叠加一次状态栏高度。实测红色顶栏起始位置：首页/自选/行情/资讯 在 **y=63**，
   交易与详情页却在 **y=126**（正好两倍）。三处都加上 `contentWindowInsets = WindowInsets(0, 0, 0, 0)` 后全部回到 63。
2. **自定义总资产修正**：原实现按「持仓成本」扣减可用资金，
   于是"设为 100 万"实际会得到 92 万出头。改为按**持仓市值**扣减（总资产 = 可用 + 市值），
   现在输入 100 万就是 1,000,000.00；弹层里也标出「其中持仓市值 X 元（保留不动）」。
   入口两个：交易首页点「总资产」，或 `多账号登录 → 账户管理`。
3. **下单改为「点了就成交」**：新增 `TradeRepository.executeImmediately()`，
   不做"委托价 vs 市价"的撮合判断，直接以**用户输入的价格**成交（因此价格完全自由，不受涨跌停限制），
   同时写入一条"已成"委托与一条成交记录。买入扣资金、卖出扣持仓。

> 本模块保留的唯一本地能力是「自定义总资产」，入口按真机结构收进 `多账号登录 → 账户管理`，不影响页面还原度。

## 第六轮：本地持久化（退出 App 不再丢数据）

此前账户与自选都只放在内存里，`TradeRepository` / `WatchlistRepository` 是 `@Singleton` + `MutableStateFlow`，
一旦进程结束（返回键退出、被系统回收、强杀），资金、持仓、委托、成交、自选全部回到初始值。

本轮加了最小改动的落盘能力：

1. **新增 `data/local` 一层**：`LocalStore` 接口 + `SharedPrefsLocalStore`（SharedPreferences 存 JSON 快照）
   + `LocalStoreModule`（Hilt 注入，`@ApplicationContext`）。不引入 Room / DataStore 等新依赖。
2. **`TradeRepository` 持久化**：资金、冻结资金、持仓、委托、成交、自增 ID 序号在每次变更后写盘
   （下单 / 撮合 / 撤单 / 立即成交 / 自定义总资产 / 重置账户），启动时自动恢复；
   首次启动无快照时才按默认持仓（茅台 / 五粮液）播种。行情轮询触发的 `tryMatch` 只有真的产生成交才写盘，避免无谓 IO。
3. **`WatchlistRepository` 持久化**：增删自选即写盘；清空后重启仍为空，不会又回退默认自选。
4. **测试不受影响**：仓库保留一个无参构造（内部用 `NoOpLocalStore`），现有 14 个纯 JVM 测试照常运行；
   另加 8 个持久化测试，用内存版 `LocalStore` 模拟"写盘 → 杀进程 → 重启读盘"，覆盖资金/持仓/挂单冻结/撤单/ID/自选等场景。

> 写盘用 `SharedPreferences.commit()` 同步落盘（数据量只有几 KB），保证"操作返回即已持久化"。
> 想回到出厂数据：交易首页「总资产」或 `多账号登录 → 账户管理` 里重置账户即可；自选直接删光即可。

## 第七轮：成交价改为「按你填的价格」

1. **问题**：交易页「买入/卖出」用的是 `executeImmediately`（按用户填的价成交），
   但从**个股详情页 / 持仓行**进去的「下单页」走的是 `placeOrder`，成交价取的是**行情现价**，
   所以填 8.88、现价 9.59 时，实际按 9.59 成交（且填低于现价的买价会变成挂单不成交）。
2. **改法**：
   - `TradeRepository.matchOrder()` 的成交价由 `marketPrice` 改为 `order.price`——撮合一律按委托价成交；
   - `OrderViewModel.submit()` 改用 `executeImmediately()`，与交易页「买入/卖出」行为一致：
     **点了就成交、填多少按多少**，不受现价与涨跌停限制。
3. **代价**：下单页不再产生"未成交挂单"，撤单页会显示「无可撤委托」（仍会列出今日成交单）；`placeOrder` 的挂单撮合逻辑保留在仓库里。
4. 版本号提升到 **1.1（versionCode 2）**，方便确认手机上装的是新包：系统设置 → 应用 → 同花顺 → 版本。

> 持久化部分在 Android 模拟器（android-34，arm64）上做过完整验证：
> 安装 → 加自选（招商银行）→ 买入浦发银行 100 股 @ 8.88 → `am force-stop` 杀进程 → 重开，
> 持仓与自选都仍在；`shared_prefs/tonghuashun_local_store.xml` 中可见 `trade_account_snapshot` 与 `watchlist_codes` 两个快照。
